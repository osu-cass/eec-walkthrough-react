\section{Introduction}
This document describes all of the API endpoints for the EEC Walkthrough application.
The document is organized by route name and each API endpoint includes a general description, the expected input, and  the expected output.

This API uses cookies to keep track of the user who is making requests. This means that each of these endpoints will have access to all user information for the current user even if it is not requested in the body. This includes ID, username, first name, last name, email, and role. All endpoints also have the option to return an error code. This will have a status code between 400 and 500. In the case of a validation error an object with the property "errors" will be returned, which is an array of objects that describe what was wrong with the request body. All other errors will return an object with the property "error", which is a string that describes the error.

To make handling responses from the API easier, all responses return a JSON object. To make it easier to tell what requests are being made to the API (as apposed to requests to get files), each API request starts with "api".

\section{API Endpoints}

\subsection{Card Endpoints}

\noindent
\textbf{\textcolor{Green}{POST} api/cards} \\
Creates a new card. Only editors and admins can use this endpoint.
\begin{itemize}
    \item HeaderId: The ID of the header that this card belongs to.
    \item cardType: The type of card to create. Examples include: default card, internal card, thumbnail gallery, internal thumbnail gallery, and more.
    \item title: The title of the card.
    \item items: The items that will be included in the card.
    \begin{itemize}
        \item cardId: The ID of the card that this item belongs to.
        \item indentation: The level of indentation (0 is none, 3 is max).
        \item iconType: The ID of the icon that is displayed at the start of the item.
        \item contentText: The main body of text for the item.
        \item contentUrl: The URL of the item. For graphic items this will be the URL of the image to display, for link items this will be the URL to direct the user to.
        \item contentLabel: The bold title of the item, this is shown before the content text.
        \item contentMode: A special setting that depends on the item in particular. For links this will be used to describe the type of link (internal, external, internal download, external download).
        \item internal: Determines if the item should be viewable by the public, or just internal users. A value of 1 is only viewable by internal users, while a value of 0 is viewable by everyone.
        \item sourceId: The ID of the source that this item is referencing.
    \end{itemize}
\end{itemize}
\begin{lstlisting}[caption=Example Request Body]
{ 
  headerId: 2,
  cardType: 0,
  title: "Best Practices",
  items: [
   {
     cardId: 1,
     indentation: 0,
     iconType: 16,
     contentText: "An informational page with analysis tools",
     contentUrl: "https://www.bpa.gov/EE/Sectors/Industrial/Pages/Co",
     contentLabel: "Bonneville Power Administration",
     contentMode: 0,
     internal: 0,
     sourceId: 2
   }
  ]
}
\end{lstlisting}
\begin{itemize}
  \item insertId: The ID of the newly created card.
\end{itemize}
\begin{lstlisting}[caption=Example Response]
{ 
  insertId: 10
}
\end{lstlisting}

\noindent
\textbf{\textcolor{BlueGreen}{PATCH} api/cards/:cardId/move/:direction/:mode} \\
Changes the selected card's position relative to other cards when displayed. If we are moving an unpublished card, it will move the card relative to all cards (excluding its published version). If we are moving a published card it will move relative to published cards (skipping over unpublished cards). Only editors or admins can move an unpublished card. Only admins can move a published card.
\begin{itemize}
    \item cardId: The ID of the card to move.
    \item direction: A value of 1 moves the card up one row. A value of 0 moves the card down one row.
    \item mode: States what type of card we want to move. A value of 0 represents an unpublished card. A value of 1 represents a published card.
\end{itemize}
\begin{lstlisting}[caption=Example Response]
{ 
  cardId: 1
}
\end{lstlisting}
\\~\\

    \end{itemize}
\end{itemize}

\subsection{File Endpoints}


\noindent
\textbf{\textcolor{Green}{POST} api/files/single} \\
Uploads a single file to the server. The file must use one of the following filename extensions: JPG, PNG, or GIF. If a file is successfully uploaded, then it is stored in a directory that is named after the user who uploaded the file. This allows users to be accountable for the content that they upload. Only editors or admins can upload files.
\begin{itemize}
    \item fieldname: The form field name. For this endpoint it is always "image".
    \item originalname: The original file name.
    \item encoding: The file encoding.
    \item mimetype: The MIME type of the file. Similar to a filename extension.
    \item destination: The destination of the file on the server.
    \item filename: The newly generated filename.
    \item path: Similar to destination.
    \item size: The size of the file in bytes.
\end{itemize}
\begin{lstlisting}[caption=Example Request File]
{
  fieldname: "image",
  originalname: "taco.gif",
  encoding: "7bit",
  mimetype: "image/gif",
  destination: "../fontend/public/uploads/user_42/",
  filename: "4fd7f3a50a0c63f368806aad8c36c3c5.gif",
  path: "..\\frontend\\public\\uploads\\user_42\\4fd7f3a50a0c63f368806aad8c36c3c5.gif",
  size: 487495
}
\end{lstlisting}
\begin{itemize}
    \item url: The address that points to the newly uploaded file.
\end{itemize}
\begin{lstlisting}[caption=Example Response]
{ 
  url: "/uploads/user_42/4fd7f3a50a0c63f368806aad8c36c3c5.gif"
}
\end{lstlisting}
\\~\\

Creates a new header. Only editors and admins can use this endpoint.

    \item title: The title of the header.

\subsection{Link Endpoints}


\noindent
\textbf{\textcolor{Green}{POST} api/links/all} \\
Returns a list of all of the published link items. Only admins can use this endpoint.
\begin{itemize}
    \item onlyDead: This value determines if we want to view all published links or just published links that have been marked invalid (0 = all links, 1 = invalid links only)
    \item sort: The value to sort results by (0 = last confirmed valid time, 1 = title, 2 = url).
    \item order: The order in which to display results (0 = descending, 1 = ascending).
    \item cursorPrimary: This cursor should contain the value that we are sorting by of the link that we want to start our results with. This cursor is used to allow infinite scrolling, while only loading a small number of page results at a time. If this is a new search then this value should be null.
    \item cursorSecondary: This cursor should contain the item ID of the link that we want to start our results with. This cursor is used in instances where the primary cursor value is ambiguous. If this is a new search then this value should be null.
\end{itemize}
\begin{lstlisting}[caption=Example Request Body]
{
  onlyDead: 0,
  sort: 0,
  order: 1,
  cursorPrimary: "null"
  cursorSecondary: "null"
}
\end{lstlisting}
\begin{itemize}
    \item links: All links.
    \begin{itemize}
        \item itemId: The ID of the link item.
        \item time: The time the link was last confirmed valid. This value is null if the link is currently invalid.
        \item unixTime: The time the link was last confirmed valid. This value is represented as the number of seconds that have elapsed since the Unix epoch. This value is null if the link is currently invalid.
        \item title: The text that the link is embedded in.
        \item url: The URL for the link.
    \end{itemize}
    \item nextCursor: An object that contains the information needed to continue getting the remaining results.
    \begin{itemize}
        \item cursorPrimary: This cursor should contain the value that we are sorting by of the link that should appear next in the search results. If this is null, then there are no more links.
        \item cursorSecondary: This cursor should contain the item ID of the link that should appear next in the search results. If this is null, then there are no more links.
    \end{itemize}
\end{itemize}
\begin{lstlisting}[caption=Example Response]
{

\noindent
\textbf{\textcolor{Green}{POST} api/users/search} \\
Returns a limited list of users that match the search text and that only includes users that are at or beyond the cursor. The search text can find matches for first name, last name, username, email, or user ID. Only admins can use this endpoint.
\begin{itemize}
    \item text: The partial or full text that is used to find a match. Partial matches are allowed. For example: searching for "oh" would be able to return "John123" since "oh" is contained with in "John123".
    \item role: The role to filter results by (0 = any, 1 = external user, 2 = internal user, 3 = editor, 4 = admin).
    \item sort: The value to sort results by (0 = username, 1 = name, 2 = user ID, 3 = email, 4 = created, 5 = role).
    \item order: The order in which to display results (0 = descending, 1 = ascending).
    \item cursorPrimary: This cursor should contain the value that we are sorting by of the user we want to start our search at. This cursor is used to allow infinite scrolling, while only loading a small number of page results at a time. If this is a new search then this value should be null.
    \item cursorSecondary: This cursor should contain the user ID of the user you want to start your search at. This cursor is used in instances where the primary cursor value is ambiguous. If this is a new search then this value should be null.
\end{itemize}
\begin{lstlisting}[caption=Example Request Body]
{
  text: "oregonstate",
  role: 0,
  sort: 0,
  order: 1,
  cursorPrimary: "null",
  cursorSecondary: "null"
}
\end{lstlisting}
\begin{itemize}
    \item users: The users returned from the search.
    \begin{itemize}
        \item created: The date that the user account was created.
        \item createdUnix: The date that the user account was created. This value is represented as the number of seconds that have elapsed since the Unix epoch.
        \item email: The user's email address.
        \item firstName: The user's first name.
        \item lastName: The user's last name.
        \item role: The user's role (0 = not logged in, 1 = external user, 2 = internal user, 3 = editor, 4 = admin).
        \item username: The user's username.
    \end{itemize}
    \item nextCursor: An object that contains the information needed to continue getting the remaining search results.
    \begin{itemize}
        \item cursorPrimary: This cursor should contain the value that we are sorting by of the user we that should appear next in the search results. If this is null, then there are no more users.
        \item cursorSecondary: This cursor should contain the user ID of the user that should appear next in the search results. If this is null, then there are no more users.
    \end{itemize}
\end{itemize}
\begin{lstlisting}[caption=Example Response]
{
  users: [
    {
      created: "2020-09-01T02:00:00.000Z",
      createdUnix: 1598925600,
      email: "testeditor@oregonstate.edu",
      firstName: "John",
      lastName: "Doe",
      role: 3,
      userId: 67,
      username: "testEditor"
    }
  ]
  nextCursor: {
    primary: null,
    secondary: null
  },
}
\end{lstlisting}
\\~\\

\subsection{View Endpoints}


\noindent
\textbf{\textcolor{RoyalBlue}{GET} api/views/page/:pageId} \\
Returns all of the views available to the current user for the specific page. Any user can use this endpoint.
\begin{itemize}
    \item pageId: The ID of the page to get the views for.
    \item views: The views that can be accessed on this page.
    \begin{itemize}
      \item pageId: The page that this view belongs to.
      \item public: Whether this view is viewable by all users (1) or only viewable by the current user (0).
      \item userId: The user ID of the user who created this view.
      \item viewId: The ID of the view.
      \item viewName: The name of the view.
      \item headers: The headers and their filter settings for the current view.
      \begin{itemize}
        \item headerId: The ID of the current header.
        \item filters: An array of filter icon IDs. Each value represents a specific filter that is disabled on the current header while in this view.
      \end{itemize}
    \end{itemize}
\end{itemize}

\begin{lstlisting}[caption=Example Response]
{
  views: [
    {
      pageId: 2,
      public: 1,
      userId: 51,
      viewId: 11,
      viewName: "Opportunities",
      headers: [
        {
          headerId: 1,
          filters: [1, 2, 3, 4, 5]
        }
      ]
    }
  ]
}
\end{lstlisting}
\\~\\

    \item viewName: The name of the new view.
    \item headers: The headers and their filter settings for the current view.
      \begin{itemize}
        \item headerId: The ID of the current header.
        \item filters: An array of filter icon IDs. Each value represents a specific filter that is disabled on the current header while in this view.
      \end{itemize}
\end{itemize}
\begin{lstlisting}[caption=Example Request Body]
{
  publicView: 0,
  viewName: "No pros or cons",
  headers: [
    {
      headerId: 1,
      filters: [1, 2]

\begin{itemize}
